# 本地升级版：安全与可靠性修复

基于 main 的 6da16a2 开发。沿用原筛选条件与默认提示词，不加入个人简历或求职偏好，不新增附件发送、自动回复或集中审阅功能。

## 可观察的变化

- 配置／工作流构建失败不能开始投递。平台限额、频繁操作、登录／权限异常会停止整批任务；不再自动确认限额提示并继续。
- 建立沟通只请求一次。超时或断线后的结果标记待核实，不自动重发。停止会取消等待、AI 请求与可取消的站内请求，后续发送前再次检查。
- 后台为账号维护独占运行锁与动作台账，跨标签页共用去重与今日额度；刷新、页面关闭、后台重启后不会自动恢复发送。
- 岗位、HR、公司分别按各自标识去重。筛选跳过不写入已投递，已建立沟通不会因后续招呼失败而丢失。
- 模型设置在扩展自己的页面打开，Key 保存在扩展本地；AI 请求由后台执行。页面脚本不能读取扩展存储或调用任意 URL。
- 自定义 API 服务按域名申请权限，普通导出移除密钥和敏感请求头；可在模型设置中清除全部模型密钥。
- 日志页增加动作台账，分别记录建立沟通、文字和图片消息。消息提交不等于业务确认送达，也不代表发送了附件简历。

## 安装与验证

1. 初始化子模块：git submodule update --init --recursive。
2. 安装 Bun 后运行 bun install --frozen-lockfile；不需要升级依赖。TypeScript 固定为 5.9.3，避免原 TypeScript 7 与 vue-tsc 不兼容。
3. 运行 bun run check、bun run lint、bun run test。
4. 运行 bun run build:chrome／build:edge／build:firefox，加载对应的 .output/<browser>-mv3 目录。保留原浏览器支持。
5. 可运行 bun run test:browser，使用独立临时 Chrome 配置与完全模拟的 BOSS 页面验证首次挂载及限流停止。默认使用 macOS Chrome 路径；其他位置通过 BOSS_HELPER_CHROME 指定。需要支持 Extensions.loadUnpacked 调试命令的 Chrome。测试不用真实账号，测试页面的 HTTPS 请求均被拦截。

check 会先在日志子模块忽略的 dist 中生成类型声明，再检查主项目；不修改子模块源码，也不把第三方子模块测试纳入主项目测试。

## 首次使用

- 站点权限已恢复原版的 HTTP／HTTPS 网站范围，Chrome 的“On all sites”可选；页面脚本仍只匹配 BOSS 域名。AI 服务的逐域名申请逻辑会在已有权限时直接通过。
- 修复岗位组件晚于应用根组件挂载时初始化失败：等待岗位组件就绪，并检查所有候选容器，跳过不持有岗位列表的布局容器。
- 在 BOSS 登录后的岗位列表页打开插件。保留原配置入口，基础筛选不需要模型账号。
- AI 功能通过“模型配置（扩展页面）”管理；保存或测试时授权 API 域名，再返回 BOSS 页面启动任务。
- 旧同步模型配置验证写入本地后才删除，已有本地配置优先。删除旧同步值不能撤回同步服务已保留的历史副本。
- 旧版公司／HR 去重记录实际使用岗位标识，保留原数据但不再沿用为有效记录。新版今日确认数量只覆盖新版台账中的动作，平台自身限制始终优先。
- 限流、登录失效或结果不确定时，处理原因后手动启动。对待核实动作，先在 BOSS 核对实际状态，再在日志页选择“已核实成功”或“已核实未执行”；运行期间禁止修改核实结果。

## 验证边界

自动化测试与模拟浏览器验收不证明当前 BOSS 私有接口、真实 MQTT 聊天协议或任意模型服务持续兼容。未使用真实账号投递、发送消息或调用付费模型。Firefox 和 Edge 的生产构建通过也不等于完成了这两个浏览器的真实平台端到端测试。

扩展依赖网站内部数据和接口，无法保证消除账号风控。保留已有间隔和额度配置，不将任何数量声明为安全额度。API Key 采用扩展本地存储，不声称额外加密；操作系统和浏览器本身仍属于信任边界。
